# 報修登記系統
用於登記報修問題並追蹤處理進度。

## 欄位

- 報修人姓名
- 地點或部門
- 類別：設備、網路、環境、其他
- 問題說明
- 負責人
- 緊急程度：低、中、高
- 處理狀態：待處理、處理中、已完成
- 登記時間（系統自動產生）
雲端任務測試
[報修欄位表（Excel）](文件/報修欄位表.xlsx)

## 網頁與發佈

首頁為根目錄的 `index.html`，使用純 HTML/CSS/JavaScript 與 CDN 提供的 supabase-js v2。
`config.js` 僅包含可公開的 Supabase 網址及 publishable key，不得放入 secret 或 service_role 金鑰。

在 GitHub 的 Settings → Pages 選擇「Deploy from a branch」，來源設為 `main`、`/ (root)`。
預期網址：https://cj2vum4.github.io/repair-system/ （需先啟用 Pages 並等待部署完成）。

請先在 Supabase 建立 `supabase/schema.sql` 所定義的資料表與權限；加入 SQL 檔或部署前端不會自動執行 SQL。
表單僅新增五個輸入欄位，`id`、`created_at`、`status` 使用資料庫預設值；清單公開顯示最近 20 筆。

## 報修清單緊急程度篩選

- 清單上方提供「全部、高、中、低」，預設選取「全部」，選中的按鈕以深綠底白字標示。
- 篩選僅使用網頁已載入的最近 20 筆報修，不會因切換按鈕額外查詢資料庫；筆數顯示目前符合篩選的數量，無符合資料時顯示提示。
- 「高」緊急程度以紅色標籤顯示。重新整理清單後保留目前篩選。
- 本次僅修改網頁與說明文件，未更動資料庫、未新增欄位，也未修改 `supabase/`。

手機確認：開啟此分支的預覽網頁，向下滑到「最近報修」，確認預設選中「全部」；依序點「高、中、低」檢查只顯示對應紀錄、選中按鈕清楚可辨，再點「全部」恢復清單。「高」的標籤應為紅色。選擇某個篩選後按「重新整理」，確認選取狀態保留。篩選範圍限最近 20 筆，沒有符合資料時應顯示提示。PR 尚未合併及部署前，正式 main 網址不會顯示這次變更。
